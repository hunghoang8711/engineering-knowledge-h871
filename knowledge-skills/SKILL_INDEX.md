## Add a skill when
A technique has been used more than once, a non-obvious API/engine constraint was discovered, a failure was diagnosed, or the user has a durable preference that changes future implementation. Each skill should include scope, invariants, workflow, pitfalls, tests, and links to source/history where possible.
